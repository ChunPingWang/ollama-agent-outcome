# Spec 001 — 個人資料管理

## 背景
系統需要為使用者提供管理個人基本資料的功能，包含建立、查詢、更新與刪除個人資料。此功能需確保資料的完整性與一致性，並提供清晰的錯誤回應以協助前端或客戶端進行錯誤處理。

## 名詞
- **個人資料 (Profile)**：代表單一使用者的基本資訊集合，包含唯一識別碼、電子郵件、姓名與年齡。
- **電子郵件 (Email)**：用於識別使用者的唯一字串，需符合標準電子郵件格式。
- **姓名 (Name)**：使用者的顯示名稱，不可為空。
- **年齡 (Age)**：使用者的年齡，需為正整數。

## 使用者情境

### US-1 建立個人資料
身為系統管理員，我想要建立新的個人資料，以便在系統中註冊新使用者。

### US-2 查詢個人資料
身為使用者，我想要透過 ID 查詢我的個人資料，以便確認我的資料是否正確。

### US-3 更新個人資料
身為使用者，我想要更新我的個人資料，以便修正錯誤資訊或更新現況。

### US-4 刪除個人資料
身為系統管理員，我想要刪除不再需要的個人資料，以便維護系統資料的潔淨。

## 驗收條件

```gherkin
功能: 個人資料 CRUD 操作
    作為系統管理員或使用者
    我想要對個人資料進行新增、查詢、更新與刪除
    以便管理使用者資料

    場景: 成功建立個人資料
        假設 系統中尚無電子郵件為 "user@example.com" 的個人資料
        當 我提交 POST 請求至 "/profiles"，內容包含:
            | 欄位     | 值               |
            | email    | user@example.com |
            | name     | 測試使用者       |
            | age      | 25               |
        那麼 回應狀態碼應為 201 Created
        並且 回應標頭 "Location" 應指向新建立的資源
        並且 回應主體應包含新建立的個人資料 ID

    場景: 建立個人資料時電子郵件格式錯誤
        當 我提交 POST 請求至 "/profiles"，內容包含:
            | 欄位     | 值             |
            | email    | invalid-email  |
            | name     | 測試使用者     |
            | age      | 25             |
        那麼 回應狀態碼應為 400 Bad Request
        並且 回應主體應包含錯誤訊息說明電子郵件格式不正確

    場景: 建立個人資料時姓名為空
        當 我提交 POST 請求至 "/profiles"，內容包含:
            | 欄位     | 值             |
            | email    | user2@example.com |
            | name     |                |
            | age      | 25             |
        那麼 回應狀態碼應為 400 Bad Request
        並且 回應主體應包含錯誤訊息說明姓名不可為空

    場景: 建立個人資料時年齡為負數
        當 我提交 POST 請求至 "/profiles"，內容包含:
            | 欄位     | 值             |
            | email    | user3@example.com |
            | name     | 測試使用者     |
            | age      | -1             |
        那麼 回應狀態碼應為 400 Bad Request
        並且 回應主體應包含錯誤訊息說明年齡必須為正整數

    場景: 建立個人資料時電子郵件已存在
        假設 系統中已存在電子郵件為 "duplicate@example.com" 的個人資料
        當 我提交 POST 請求至 "/profiles"，內容包含:
            | 欄位     | 值                  |
            | email    | duplicate@example.com |
            | name     | 重複使用者         |
            | age      | 30                  |
        那麼 回應狀態碼應為 409 Conflict
        並且 回應主體應包含錯誤訊息說明電子郵件已存在

    場景: 成功查詢存在的個人資料
        假設 系統中存在 ID 為 "123e4567-e89b-12d3-a456-426614174000" 的個人資料
        當 我提交 GET 請求至 "/profiles/123e4567-e89b-12d3-a456-426614174000"
        那麼 回應狀態碼應為 200 OK
        並且 回應主體應包含該個人資料的詳細資訊

    場景: 查詢不存在的個人資料
        當 我提交 GET 請求至 "/profiles/00000000-0000-0000-0000-000000000000"
        那麼 回應狀態碼應為 404 Not Found
        並且 回應主體應包含錯誤訊息說明找不到該個人資料

    場景: 成功更新個人資料
        假設 系統中存在 ID 為 "123e4567-e89b-12d3-a456-426614174000" 的個人資料，姓名為 "舊姓名"
        當 我提交 PUT 請求至 "/profiles/123e4567-e89b-12d3-a456-426614174000"，內容包含:
            | 欄位     | 值               |
            | email    | user@example.com |
            | name     | 新姓名           |
            | age      | 26               |
        那麼 回應狀態碼應為 200 OK
        並且 回應主體應包含更新後的個人資料資訊
        並且 該個人資料的姓名應變更為 "新姓名"

    場景: 更新不存在的個人資料
        當 我提交 PUT 請求至 "/profiles/00000000-0000-0000-0000-000000000000"，內容包含:
            | 欄位     | 值               |
            | email    | user@example.com |
            | name     | 新姓名           |
            | age      | 26               |
        那麼 回應狀態碼應為 404 Not Found
        並且 回應主體應包含錯誤訊息說明找不到該個人資料

    場景: 成功刪除個人資料
        假設 系統中存在 ID 為 "123e4567-e89b-12d3-a456-426614174000" 的個人資料
        當 我提交 DELETE 請求至 "/profiles/123e4567-e89b-12d3-a456-426614174000"
        那麼 回應狀態碼應為 204 No Content
        並且 再次查詢該 ID 應返回 404 Not Found

    場景: 刪除不存在的個人資料
        當 我提交 DELETE 請求至 "/profiles/00000000-0000-0000-0000-000000000000"
        那麼 回應狀態碼應為 404 Not Found
        並且 回應主體應包含錯誤訊息說明找不到該個人資料
```

## API 概要

| HTTP 方法 | 路徑                              | 成功狀態碼 | 失敗狀態碼 | 說明                     |
|-----------|-----------------------------------|------------|------------|--------------------------|
| POST      | /profiles                         | 201        | 400, 409   | 建立新個人資料           |
| GET       | /profiles/{id}                    | 200        | 404        | 查詢單一個人資料         |
| PUT       | /profiles/{id}                    | 200        | 400, 404   | 全量更新個人資料         |
| DELETE    | /profiles/{id}                    | 204        | 404        | 刪除個人資料             |

## 範圍外

- 使用者認證與授權（假設所有請求均來自已認證使用者或管理員）。
