# Spec 001 — 個人資料管理

## 背景
系統需要為使用者提供管理個人資料的功能，包括建立新的個人資料、查詢現有資料、更新個人資訊以及刪除不再需要的資料。此功能需確保資料的完整性與一致性，並提供清晰的錯誤回饋。

## 名詞
- **個人資料 (Profile)**：代表一個使用者的基本資訊集合，包含唯一識別碼、姓名、電子郵件地址等欄位。
- **電子郵件 (Email)**：用於識別使用者的唯一字串，需符合標準電子郵件格式，且在系統中必須唯一。
- **識別碼 (ID)**：系統自動產生的唯一識別字，用於標識每一筆個人資料。

## 使用者情境

### US-1 建立個人資料
身為系統使用者，我想要建立新的個人資料，以便在系統中註冊我的基本資訊。

### US-2 查詢個人資料
身為系統使用者，我想要透過識別碼查詢特定的個人資料，以便確認資料內容或進行後續操作。

### US-3 更新個人資料
身為系統使用者，我想要更新我的個人資料，以便修正錯誤資訊或更新現況。

### US-4 刪除個人資料
身為系統使用者，我想要刪除我的個人資料，以便移除不再需要的資料或符合隱私法規要求。

## 驗收條件

```gherkin
功能: 個人資料 CRUD 操作
  作為: 系統使用者
  想要: 管理個人資料
  以便: 維護個人資訊的正確性與完整性

  場景: 成功建立個人資料
    假設 沒有重複的電子郵件
    當 我提交包含有效姓名與電子郵件的個人資料建立請求
    那麼 系統應回傳 201 Created 狀態碼
    並且 回應內容應包含新生成的識別碼
    並且 系統中應存在該筆個人資料

  場景: 建立個人資料時電子郵件重複
    假設 系統中已存在電子郵件為 "user@example.com" 的個人資料
    當 我提交包含電子郵件 "user@example.com" 的個人資料建立請求
    那麼 系統應回傳 409 Conflict 狀態碼
    並且 錯誤訊息應指出電子郵件已存在

  場景: 建立個人資料時電子郵件格式無效
    當 我提交包含格式錯誤電子郵件（如 "invalid-email"）的個人資料建立請求
    那麼 系統應回傳 400 Bad Request 狀態碼
    並且 錯誤訊息應指出電子郵件格式不正確

  場景: 成功查詢存在的個人資料
    假設 系統中存在識別碼為 "uuid-123" 的個人資料
    當 我查詢識別碼為 "uuid-123" 的個人資料
    那麼 系統應回傳 200 OK 狀態碼
    並且 回應內容應包含該筆個人資料的詳細資訊

  場景: 查詢不存在的個人資料
    當 我查詢識別碼為 "non-existent-id" 的個人資料
    那麼 系統應回傳 404 Not Found 狀態碼
    並且 錯誤訊息應指出該個人資料不存在

  場景: 成功更新個人資料
    假設 系統中存在識別碼為 "uuid-123" 的個人資料，姓名為 "Old Name"
    當 我提交更新請求，將姓名改為 "New Name"
    那麼 系統應回傳 200 OK 狀態碼
    並且 系統中該筆資料的姓名應更新為 "New Name"
    並且 其他未修改的欄位應保持不變

  場景: 更新不存在的個人資料
    當 我嘗試更新識別碼為 "non-existent-id" 的個人資料
    那麼 系統應回傳 404 Not Found 狀態碼
    並且 錯誤訊息應指出該個人資料不存在

  場景: 成功刪除個人資料
    假設 系統中存在識別碼為 "uuid-123" 的個人資料
    當 我刪除識別碼為 "uuid-123" 的個人資料
    那麼 系統應回傳 204 No Content 狀態碼
    並且 系統中該筆個人資料應被移除
    並且 後續查詢該識別碼應回傳 404 Not Found

  場景: 刪除不存在的個人資料
    當 我嘗試刪除識別碼為 "non-existent-id" 的個人資料
    那麼 系統應回傳 404 Not Found 狀態碼
    並且 錯誤訊息應指出該個人資料不存在
```

## API 概要

| HTTP 方法 | 路徑 | 描述 | 成功狀態碼 | 失敗狀態碼 |
| :--- | :--- | :--- | :--- | :--- |
| POST | `/api/profiles` | 建立新個人資料 | 201 Created | 400 Bad Request, 409 Conflict |
| GET | `/api/profiles/{id}` | 查詢單一個人資料 | 200 OK | 404 Not Found |
| PUT | `/api/profiles/{id}` | 更新單一個人資料 | 200 OK | 400 Bad Request, 404 Not Found |
| DELETE | `/api/profiles/{id}` | 刪除單一個人資料 | 204 No Content | 404 Not Found |

## 範圍外
- 個人資料的分頁與列表查詢（僅支援單一查詢）。
- 個人資料的權限控制（假設所有操作均為合法使用者）。
- 個人資料的歷史版本追蹤。
- 檔案上傳或附件管理。
