# Spec 001 — 個人資料管理 (Personal Profile CRUD)

## 背景
系統需要為註冊用戶提供維護個人基本資訊的功能，包括建立新的個人資料記錄、查詢現有資料、更新已存在的資訊以及刪除不再需要的資料。這確保了數據的準確性與完整性，並符合隱私保護的基本需求。

## 名詞
- **個人資料 (Profile)**：代表單一使用者的核心基本資訊集合，包含唯一識別碼、姓名、電子郵件地址等欄位。
- **電子郵件 (Email)**：用於標識使用者身份的唯一字串格式，需符合標準 Email 語法且在全域中必須唯一。
- **識別碼 (ID)**：系統自動產生的唯一識別符，用於區分不同的個人資料記錄。

## 使用者情境

### US-1 新增個人資料
身為**系統使用者**，我想要**提交我的基本資訊來建立一個新帳號或資料夾**，以便**後續能使用該身分進行操作**。

### US-2 查詢個人資料
身為**系統使用者**，我想要**透過 ID 查看特定的個人資料**，以便**確認資料內容是否正確**。

### US-3 修改個人資料
身為**系統使用者**，我想要**更新我現有的個人資料（如更改姓名）**，以便**保持資訊的最新狀態**。

### US-4 刪除個人資料
身為**系統管理者**或**擁有權限的使用者**，我想要**永久移除某筆個人資料**，以便**清理無效或過期的數據**。

## 驗收條件

```gherkin
功能: 個人資料 CRUD 管理
    作為一名使用者，我需要能夠對個人資料執行增刪改查操作，以確保資料的準確性與完整性。

    場景大纲: 成功新增個人資料
        假設 沒有重複的電子郵件
        當 我發送 POST 請求至 "/profiles"，內容包含:
            """json
            {
              "name": "<名稱>",
              "email": "<電子郵件>"
            }
            """
        那麼 HTTP 回應狀態碼應為 201 Created
        並且 回應標頭 "Location" 不應為空
        並且 我可以透過該 Location 路徑查詢到剛建立的資料

    範例:
        | 名稱     | 電子郵件             |
        |----------|----------------------|
        | 王小明   | wang@example.com     |
        | 李阿美   | li@example.com       |

    場景: 嘗試建立已有相同電子郵件的新資料
        假設 已存在一筆電子郵件為 "duplicate@test.com" 的個人資料
        當 我發送 POST 請求至 "/profiles"，內容包含:
            """json
            {
              "name": "新用戶",
              "email": "duplicate@test.com"
            }
            """
        那麼 HTTP 回應狀態碼應為 409 Conflict
        並且 錯誤訊息指出電子郵件重複

    場景: 新增資料時缺少必要欄位
        當 我發送 POST 請求至 "/profiles"，內容包含:
            """json
            {
              "name": ""
            }
            """
        那麼 HTTP 回應狀態碼應為 400 Bad Request
        並且 錯誤訊息指出 email 欄位為必填且格式正確

    場景: 成功查詢存在的個人資料
        假設 系統中存在 ID 為 <id> 的個人資料
        當 我發送 GET 請求至 "/profiles/<id>"
        那麼 HTTP 回應狀態碼應為 200 OK
        並且 回傳的 JSON 中 name 等於 "<名稱>"
        並且 回傳的 JSON 中 email 等於 "<電子郵件>"

    範例:
        | id   | 名稱     | 電子郵件             |
        |------|----------|----------------------|
        | 1    | 王小明   | wang@example.com     |

    場景: 查詢不存在的個人資料
        當 我發送 GET 請求至 "/profiles/99999"（該 ID 不存在）
        那麼 HTTP 回應狀態碼應為 404 Not Found
        並且 錯誤訊息指出找不到該筆資料

    場景: 成功更新個人資料
        假設 系統中存在 ID 為 <id> 的個人資料，目前名稱為 "舊名字"
        當 我發送 PUT 請求至 "/profiles/<id>"，內容包含:
            """json
            {
              "name": "新名字",
              "email": "<電子郵件>"
            }
            """
        那麼 HTTP 回應狀態碼應為 200 OK
        並且 再次查詢該 ID，其 name 變更為 "新名字"
        並且 email 保持不變

    場景: 嘗試更新不存在的資料
        當 我發送 PUT 請求至 "/profiles/88888"，內容包含:
            """json
            {
              "name": "無效用戶",
              "email": "invalid@test.com"
            }
            """
        那麼 HTTP 回應狀態碼應為 404 Not Found

    場景: 刪除存在的個人資料
        假設 系統中存在 ID 為 <id> 的個人資料
        當 我發送 DELETE 請求至 "/profiles/<id>"
        那麼 HTTP 回應狀態碼應為 204 No Content
        並且 隨後發送 GET 請求至同一路徑時，回傳 404 Not Found

    場景: 刪除不存在的資料
        當 我發送 DELETE 請求至 "/profiles/77777"（該 ID 不存在）
        那麼 HTTP 回應狀態碼應為 404 Not Found
```

## API 概要

| 方法     | 路徑               | 成功狀態碼 | 失敗狀態碼       | 說明                     |
|----------|--------------------|------------|------------------|--------------------------|
| POST     | /profiles          | 201        | 400, 409         | 建立新個人資料           |
| GET      | /profiles/{id}     | 200        | 404              | 查詢單一個人資料         |
| PUT      | /profiles/{id}     | 200        | 400, 404, 409    | 全量更新個人資料         |
| DELETE   | /profiles/{id}     | 204        | 404              | 刪除個人資料             |
