# Spec 001 — 個人資料管理 (Personal Profile CRUD)

## 背景
系統需要為註冊用戶提供維護個人基本資訊的功能。用戶可以建立自己的個人資料，並隨時查看、修改或刪除該資料，確保資訊的準確性與即時性。

## 名詞
- **個人資料 (Profile)**：代表單一用戶的基本資訊集合，包含唯一識別碼、姓名、電子郵件地址等核心屬性。
- **電子郵件**：用於標識用戶的唯一憑證，格式需符合標準 Email 規範，且在系統中必須保持唯一。
- **識別碼 (ID)**：系統自動產生的全局唯一識別符，用於定位特定的個人資料記錄。

## 使用者情境

### US-1 新增個人資料
身為一名新用戶，我想要建立我的個人資料以便開始使用系統服務。

### US-2 查詢個人資料
身為一名已登入用戶，我想要根據 ID 查詢我的詳細資料以便確認當前資訊狀態。

### US-3 更新個人資料
身為一名已登入用戶，我想要修改我的個人資料（如姓名）以便反映最新的生活狀況。

### US-4 刪除個人資料
身為一名已登入用戶，我想要刪除我的個人資料以便終止帳戶或移除敏感數據。

## 驗收條件

```gherkin
功能: 個人資料 CRUD 操作
    作為一名用戶
    我希望能夠管理我的個人資料
    
    場景: 成功建立新的個人資料
        假設 我發送 POST 請求至 "/profiles"，內容包含:
            """
            {
              "name": "王小明",
              "email": "xiaoming@example.com"
            }
            """
        那麼 回應的狀態碼應該是 201 Created
        並且 回應標頭 "Location" 應該存在
        
    場景: 嘗試建立重複電子郵件的個人資料失敗
        假設 我已擁有一筆電子郵件為 "duplicate@test.com" 的個人資料
        當 我發送 POST 請求至 "/profiles"，內容包含:
            """
            {
              "name": "李大明",
              "email": "duplicate@test.com"
            }
            """
        那麼 回應的狀態碼應該是 409 Conflict
        並且 錯誤訊息應指出電子郵件已被使用
        
    場景: 查詢不存在的個人資料
        當 我發送 GET 請求至 "/profiles/00000000-0000-0000-0000-000000000000"
        那麼 回應的狀態碼應該是 404 Not Found

    場景: 成功更新個人資料
        假設 已存在一筆 ID 為 "{uuid}"、姓名為 "舊名字"、Email 為 "old@example.com" 的資料
        當 我發送 PUT 請求至 "/profiles/{uuid}"，內容包含:
            """
            {
              "name": "新名字",
              "email": "new@example.com"
            }
            """
        那麼 回應的狀態碼應該是 200 OK
        並且 再次查詢該 ID 時，姓名應變更為 "新名字"
        
    場景: 嘗試更新不存在的個人資料
        當 我發送 PUT 請求至 "/profiles/00000000-0000-0000-0000-000000000000"，內容包含:
            """
            {
              "name": "無名氏",
              "email": "noone@test.com"
            }
            """
        那麼 回應的狀態碼應該是 404 Not Found
        
    場景: 成功刪除個人資料
        假設 已存在一筆 ID 為 "{uuid}" 的資料
        當 我發送 DELETE 請求至 "/profiles/{uuid}"
        那麼 回應的狀態碼應該是 204 No Content
        並且 隨後查詢該 ID 時應返回 404 Not Found

    場景: 輸入格式錯誤的電子郵件
        當 我發送 POST 請求至 "/profiles"，內容包含:
            """
            {
              "name": "測試用戶",
              "email": "invalid-email-format"
            }
            """
        那麼 回應的狀態碼應該是 400 Bad Request
```

## API 概要

| HTTP Method | Path | Description | Success Status | Error Status |
| :--- | :--- | :--- | :--- | :--- |
| `POST` | `/profiles` | 建立新個人資料 | 201 Created | 400 (驗證失敗), 409 (重複) |
| `GET` | `/profiles/{id}` | 根據 ID 查詢資料 | 200 OK | 404 (找不到) |
| `PUT` | `/profiles/{id}` | 全量更新資料 | 200 OK | 400 (驗證失敗), 404 (找不到) |
| `DELETE` | `/profiles/{id}` | 刪除指定資料 | 204 No Content | 404 (找不到) |

## 範圍外
- 目前不支援批量操作（Batch Create/Update/Delete）。
- 目前不支援檔案上傳或頭像功能。
- 目前不支援複雜的搜尋條件（如依姓名模糊搜尋），僅限依 ID 精確查詢。
- 權限控制（AuthN/AuthZ）不在本規格書範圍內，假設所有請求均來自已認證用戶或由管理後台直接呼叫。
